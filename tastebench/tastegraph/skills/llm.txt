# TasteGraph agent skills (llm.txt)

TasteGraph is open taste infrastructure for builders. Use these skills to personalize
(search, rerank, ask, explain), expose preference to agents, and keep drafts on-taste —
without baking domain logic into the model.

## Setup

```bash
pip install -e ".[tastegraph,web]"
tastebench tastegraph serve --assets data/tastegraph_assets.jsonl --port 8000
tastebench tastegraph seed-demo   # other terminal: seed the demo graph (idempotent)
```

Base URL: `http://127.0.0.1:8000` (or your deploy). Optional header: `X-API-Key`.

Installable skill (curl/HTTP recipes for agents): `skills/tastegraph/SKILL.md`.

Fetch live tool schemas:

```bash
curl -s http://127.0.0.1:8000/v1/skills
```

Or load from the package: `tastebench/tastegraph/skills/tools.json`.

## Tools → HTTP

| Tool | HTTP |
|------|------|
| taste_context | GET /agent-context/{user_id} |
| taste_search | POST /v1/search `{"user_id","k"}` |
| taste_rerank | POST /v1/rerank `{"user_id","candidates"}` |
| taste_ask | POST /v1/ask `{"user_id","question"}` |
| taste_explain | POST /v1/explain `{"user_id","candidates":[]}` |
| taste_metrics | GET /metrics |
| taste_brand_ingest | POST /v1/brand/ingest `{"id","type","references":[…]}` |
| taste_enhance | POST /v1/enhance `{"subject_id","prompt"}` |
| taste_judge | POST /v1/judge `{"subject_id","candidates":[…]}` |

## Minimal loops

**Personalize**

1. Create user + content (`POST /v1/entity`).
2. Build taste (`POST /v1/entity/{user}/link`).
3. Call taste_search / taste_rerank / taste_ask / taste_context.

**Less slop**

1. Optional: `taste_brand_ingest` with reference snippets (voice, design copy, …).
2. `taste_enhance` a draft against that `subject_id` (or a user subject).
3. `taste_judge` competing drafts before send.
